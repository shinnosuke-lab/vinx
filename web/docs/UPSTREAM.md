# The forked engine and chat UI

The agent engine (`vendor/engine/`, Rust) and the chat UI (`vendor/ui/`, its
own npm project) are a **fork** of `agent-core`, not a mirror of it. They
started as verbatim copies pinned to one upstream commit, were three-way merged
up to upstream's `main` HEAD (`10fdab3`, 2026-08-18) on 2026-08-19, and are
edited directly ever since. Upstream is a private `agent-core` repository
(branch `main`). There is no sync script and no patch directory: change these
files the way you would change any other file in this repository.

`vendor/VENDOR.json` records the fork point and lists, file by file, what was
taken, what is reimplemented for the browser, and why. The short version:

- The **engine** compiles for `wasm32-unknown-unknown` because the browser
  adaptations are baked into the sources: `wasmtimer` where upstream reads the
  tokio clock, `crate::vfs` where its tool layer touched `std::fs`, no worker
  threads. A handful of host modules it reaches by name — config, the session
  store, the theme registry — are answered by browser-native versions under
  `crates/agent-web-core/src/`.
- The **UI** is source, built here as its own npm project (`@vinx/agent-chat`),
  so the page builds against a UI from the same fork point as the engine. Its
  build output is `dist/`, which `vite.config.ts` aliases the package name
  onto.
- What was **never taken** is anything host-side: the process/filesystem tool
  layer, the real HTTP server (the routes become an in-page fetch shim), and
  the PTY terminal (replaced here by the v86 serial console).

## History: how it got here

1. **Vendored + patched** (until 2026-08-18): copies pinned at `95d5e8b`
   (v0.3.1), regenerated by a sync script, adapted by patch files. That
   machinery assumed an upstream worth tracking.
2. **Forked** (2026-08-18): a squashed working-copy snapshot (`d004748`, whose
   tree equals upstream's real commit `1bc3c71`) was merged in (three-way: pin
   as base, the patched copies as ours) and the patch machinery deleted.
3. **Synced to `10fdab3`** (2026-08-19): the six commits after `1bc3c71` were
   three-way merged in. That brought the compaction data-loss fix (request
   views — pruning only affects what is sent, the canonical history keeps full
   content — plus pre-compaction archive generations with
   `GET /api/sessions/{id}/archive[/{generation}]`), the `model_caps` table and
   the reasoning-effort plumbing (wire profiles, the UI's effort switcher),
   the `task` tool's structured reports, per-task cancel
   (`POST /api/chat/task/cancel`) and its dedicated tool card, the reworked
   queue panel, and mermaid rendering in chat markdown. Two commits were
   skipped as inapplicable here: `5ecc29a` (search_skills prompt guidance — no
   such model tools in this fork) and `345721e` (shared default API key in
   `config.rs` — config here is injected at build time).
4. **Sub-agent fixes ported** (2026-08-24, from an agent-core working-copy
   snapshot, post-`10fdab3`): `agent_task.rs` gained the soft-deadline wrap-up
   (a steer channel into the child plus a `wrap_up` select arm — `min(60s,
   budget/5)` before the hard budget the child is told to stop exploring and
   write its final report, so a timeout salvages a report instead of
   discarding the work; the disabled arm parks on this fork's `86_400`s sleep
   rather than upstream's `u64::MAX / 2`, for the browser's i32-millis timers)
   and the `synced` gate (`transcript_session_id` is only reported after a
   `SessionSync` actually reached the store); `agent_loop.rs` gained the
   round-boundary `emit_sync` (each completed tool round is persisted, so a
   crash/panic/timeout later in the turn still leaves an auditable
   transcript). Skipped as inapplicable: upstream's panic join + bounded
   reaping of the child `JoinHandle` — children here are `spawn_local` +
   `AbortHandle`, so there is no `JoinHandle` to join, no panic payload to
   read (wasm panics reach the console via the panic hook), and no join to
   hang. In the host layer (not the vendor tree), upstream's
   `src/web/session_tools.rs` was ported as
   `crates/agent-web-core/src/session_tools.rs`: `read_session` /
   `search_sessions` over this port's `SessionStore`, including the
   `resolve_id_prefix` direct-lookup semantics that keep hidden `task`
   transcripts readable by the id a task report carries. It had never been
   vendored — the host layer here is a rewrite, and the tools simply were not
   carried when it was written.

If a later upstream change is worth taking, three-way merge it per file
(`git merge-file`, base = the recorded fork commit, theirs = upstream `main`,
ours = the file here), then re-apply judgment where the wasm adaptations and
the branding diverge — exactly how the syncs above were done.

## What this repository changed on top of the fork point

The one architectural departure worth knowing: upstream's device is a gateway
(or a local shell) reached over HTTP, and its terminal is a PTY over WebSocket.
Here the device is a Linux VM emulated in the page (v86):

- `run_shell` calls leave the engine as an HTTP POST that the worker's own
  `fetch` intercepts and bounces to the main thread, where they run on the VM's
  `ttyS1` serial line (`runtime/src/worker.ts`, `runtime/src/device-vm.ts`).
- The `/terminal` console is xterm.js wired straight to the VM's `ttyS0`
  (`app/terminal.tsx`, `app/vm.ts`), not a PTY over a socket.

The browser adaptations formerly carried as patches are now plain code in the
fork. For the record, they were: wasm clocks (`wasmtimer`), the VFS rewrite of
the file tools and skill loading, single-threaded compaction archiving, the
terminal chat panel and its quality pass, tool-card summaries, the clipboard
helper export, and hiding the gateway enabled/port section of the settings
page.
